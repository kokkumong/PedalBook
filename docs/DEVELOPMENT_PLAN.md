# PedalBook 단계별 개발 계획

작성 기준: 2026-10-30 · 사용자 합의 반영: 페달 배치 편집기부터 완성한 뒤 뮬 연결과 시세 기능을 개발한다.

## 1. 개발 방향

PedalPlayground의 핵심 사용 방식인 ‘실제 규격으로 페달보드 배치하기’를 참고한다. 화면과 코드는 PedalBook에 맞게 새로 구현하고, 외부 카탈로그·이미지는 사용 범위를 확인한 항목만 도입한다.

**개발 순서는 ① 배치 편집기 → ② 뮬 페이지 연결 → ③ 참고 시세·예산 → ④ 자동 수집·캐시 고도화다.**

첫 번째 출시 단위는 외부 사이트 없이도 사용할 수 있는 배치 편집기다. 뮬 접근, 데이터 파이프라인, 로그인, PostgreSQL, Redis를 편집기 완성의 선행 조건으로 두지 않는다. 처음에는 브라우저 로컬 저장을 제공하고 계정별 서버 저장은 후속으로 연결한다.

| 단계 | 사용자가 얻는 기능 | 완료 기준 |
|---|---|---|
| 1. 배치 편집기 | 보드 규격 선택, 페달 검색·추가·이동·회전·삭제, 저장·복원 | 외부 서비스 연결 없이 한 장의 보드를 완성하고 다시 열 수 있음 |
| 2. 뮬 페이지 연결 | 선택한 페달의 브랜드/모델명으로 뮬에서 매물을 찾아보기 | 검증한 검색 URL이 해당 검색 결과를 열거나, 미지원이면 장터 링크와 검색어 복사 제공 |
| 3. 참고 시세·예산 | 근거·확인일·표본 수가 있는 대략적 호가, 보드별 합계 | 가격 미상·오래된 가격·사용자 입력값을 구분해 계산 |
| 4. 데이터 고도화 | 허용된 자동 수집, 모델 매칭, 시세 이력, Redis 캐시 | 허용 범위 내 라이브 연동과 실패 복구를 검증 |

단계 1 완료 후 실제 배치 사용성을 확인하고 단계 2로 넘어간다. 단계 2의 외부 링크 이동에는 크롤러가 필요하지 않다. 단계 3은 소수 모델의 검수된 자료부터 시작하며 전체 자동 수집을 먼저 구현하지 않는다.

## 2. 첫 번째 구현 범위: 배치 편집기

### 필수 기능

- [x] 사용자 지정 보드 가로·세로(mm), 기본 규격 프리셋.
- [x] 브랜드/모델명으로 검색할 수 있는 소규모 페달 카탈로그.
- [x] 실제 가로·세로 비율로 캔버스에 페달 추가.
- [x] 드래그 이동, 선택, 90도 회전, 삭제, 같은 모델 여러 개 추가.
- [x] 확대/축소 및 보드 전체 보기.
- [x] 브라우저 로컬 자동 저장과 새로고침 후 복원.
- [x] 보드 JSON 내보내기·불러오기로 로컬 백업.
- [x] 선택한 페달의 브랜드·모델·규격 표시.

### 사용성 보완

- [x] 그리드/스냅, 보드 밖 배치·페달 간 겹침 경고.
- [x] 되돌리기/다시 실행 및 키보드 이동·회전·삭제.
- [x] 이미지 로딩 실패 시 규격 사각형 대체 표시.
- [x] 저장 실패·손상된 가져오기 파일에 대한 명확한 안내.

저장은 mm 중심 좌표, 회전각, 인스턴스 ID, 페달 ID, 규격 snapshot을 사용한다. 확대 배율은 물리 규격에 영향을 주지 않는다. 페달을 임의로 늘리거나 줄이는 기능은 제공하지 않는다.

이미지 사용 범위 확인이 늦어지면 텍스트와 규격 사각형으로 시작하고, 사용자가 직접 규격을 입력하는 커스텀 페달을 지원한다. 카탈로그 전체 이관은 소수 모델의 배치 동작이 검증된 뒤 진행한다.

## 3. 두 번째 구현 범위: 뮬로 매물 찾아보기

편집기에서 페달을 선택하면 정보 패널에 ‘뮬에서 찾아보기’를 추가한다. 이동 전에 사용되는 브랜드·모델 검색어를 확인할 수 있게 한다.

- [x] 실제 뮬 검색 URL/파라미터를 확인한다.
- [x] 검증된 URL 빌더로 검색어를 인코딩한다.
- [x] 새 탭에서 원문 검색 결과를 연다.
- [x] 검색 링크 형식이 검증되지 않으면 뮬 장터 이동과 검색어 복사를 제공한다.
- [x] 버전·Mini·한정판 등 모델 차이를 검색어에 유지한다.

**이 단계는 매물 이동 기능이다. 자동 가격 수집이나 실시간 시세 제공이 완료된 것으로 표시하지 않는다.** 로그인 없이 가능한 공개 흐름을 기준으로 검증한다.

## 4. 세 번째 구현 범위: 참고 시세와 예산

처음에는 인기 모델 10~20개에 집중한다. 사용 가능한 자료를 확인해 검수된 참고 호가를 제공하고, 데이터가 없는 모델은 ‘시세 정보 없음’으로 표시한다. 사용자는 자신의 구매 예상 단가를 입력할 수 있으며, 이 값은 시장 통계와 구분한다.

- [ ] 참고 가격마다 출처·확인일·가격 유형을 기록한다.
- [ ] 표본이 있으면 중앙값과 범위, 표본 수를 표시한다.
- [ ] 자료가 적거나 오래됐으면 해당 상태를 표시한다.
- [ ] 관측 매물 호가와 실제 거래 체결 가격을 구분한다.
- [x] 모델별 단가 × 배치 수량을 합산한다.
- [x] 보유한 페달을 추가 구매 예산에서 제외할 수 있게 한다.
- [x] 미상 가격은 0원으로 처리하지 않고 누락 개수를 표시한다.
- [x] 사용자가 입력한 예상 가격을 수정·초기화할 수 있게 한다.

예: ‘확인된 6/8개 합계 680,000원 · 2개 가격 미상’. 가격 데이터가 전혀 없을 때 임의로 만든 시세를 채워 넣지 않는다.

## 5. 4주 실행 일정

1인 풀스택 개발자, 주 5일 기준의 제안 일정이다. 시작일 미정이므로 착수일부터 주차를 계산한다. 4주 안에 자동 수집까지 모두 끝내는 것을 목표로 삼지 않는다.

| 주차 | 우선 작업 | 산출물/완료 조건 |
|---|---|---|
| 1주차 | Next.js/TypeScript + React Konva, 보드 규격, 소수 카탈로그, 추가/이동/회전/삭제 | 600×300mm 보드에 5개 이상 페달을 실제 비율로 배치 |
| 2주차 | 검색/선택 패널, zoom/fit, 로컬 저장·복원, JSON 백업, undo/redo, 경계/겹침 경고 | 20개 페달 배치 → 저장 → 새로고침 복원이 동작하는 편집기 1차 완성 |
| 3주차 | 편집기 피드백 반영, 뮬 검색 경로 검증 및 링크 이동, 검색어 복사 | 선택한 모델에서 실제 장터 찾기로 이어지는 흐름 완성 |
| 4주차 | 소수 모델 참고 시세, 사용자 단가, 보유품 제외·수량별 예산, 통합 검증 | 근거와 누락을 표시하는 가격 패널·보드 예산 완성 |

주차별 일정은 앞 단계의 완료 조건이 충족되면 진행한다. 편집기 품질이 부족하면 뮬 자동화를 추가하기보다 1단계를 먼저 보완한다. 4주차 가격 자료 확보가 지연되면 사용자 단가·미상 상태까지 제공하고 시장 시세 연동은 미완료로 기록한다.

## 7. 단계별 검증

**배치 편집기:** mm↔화면 좌표 역변환, 90도 회전, zoom 후 좌표 유지, 동일 모델 복수 배치, 저장/복원 동일성, 잘못된 JSON 거부, 로컬 저장 실패 표시를 확인한다.

**뮬 연결:** 검증한 검색 결과가 올바른 브랜드·모델로 열리는지, 특수문자/한글 검색어가 인코딩되는지, 검색 지원이 없을 때 링크·복사 대안이 동작하는지 확인한다.

**참고 시세·예산:** 단가 근거·확인 시각, 가격 미상, 같은 모델 여러 개, 보유품 제외, 사용자 입력값과 시장 자료의 구분을 확인한다.

**후속 서버·자동화:** 타 사용자 보드 접근 차단, 중복 매물 제거, 상태 변경, 정상 빈 결과와 차단 구분, 캐시 신선도, 호스트 요청 예산, 실패 시 마지막 정상 데이터 유지 등을 검증한다.

## 8. 현재 상태 (2026-10-31)

PB-001~006은 Next.js/TypeScript·React Konva로 구현했습니다. mm 중심 좌표와 90도 회전, 카탈로그 5종/커스텀 페달, 검색·배치·zoom/pan·undo/redo·키보드·경고·로컬 저장·JSON 백업을 제공합니다. v1 저장본을 v2로 이관하면서 원본을 보존합니다. PB-007의 브라우저 검증과 자동 테스트를 수행하며 모바일 터치 조작은 추가 실기기 검증이 필요합니다.

PB-008은 브라우저에서 DS-1/이펙터/판매중 검색을 직접 확인했습니다. 모델명 검색어 수정·판매중/전체 선택·새 탭 검색 결과 이동과 복사/장터 대안을 제공합니다. 사진은 전체 카탈로그 확장 후 PedalPlayground 우선 → 등록된 공식 사진 → 대체 표시 순서로 연결했습니다. 자세한 출처는 ASSETS_AND_SEARCH.md를 참고합니다. PB-009는 가격 데이터 계약·신선도 처리·정보 없음 패널까지 구현했고, 검수된 실매물 가격 자료 확보는 미완료입니다. PB-010은 이 자료 없이도 직접 입력 단가, 인스턴스별 합계, 보유품 제외, 미상 개수로 사용할 수 있게 구현했습니다.

후속 우선순위는 사용성 피드백·BOSS 정면 사진 확보 → 허용된 소수 모델 가격 자료 확보 → PB-009 데이터 연결입니다. PB-011~013의 계정·DB·자동 수집은 아직 착수하지 않았습니다. 이전 SVG 프로토타입은 `npm run dev:prototype`으로 남겨 둡니다.
